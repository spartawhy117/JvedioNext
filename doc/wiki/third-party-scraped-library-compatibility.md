# 第三方抓取目录兼容说明

`第三方抓取` 用于接入已经由 MDCX、Emby 或其他工具整理的影片目录。Jvedio 会读取已有资料并保存为自己的影片数据，但不接管原目录。

## 适用方式

新建或编辑媒体库时，为已整理的扫描目录选择 `第三方抓取`，保存后点击 `扫描`。

- 适合目录中已有影片、NFO、`poster`、`thumb`、`fanart` 等本地资料的情况。
- 预检可能建议使用该类型，但不会自动改变你的选择。
- 同一文件不能同时属于 `MetaTube 抓取` 和 `第三方抓取` 两种目录源；请避免重叠目录。

## 扫描与抓取

| 你的情况 | 应点击的动作 | 结果 |
| --- | --- | --- |
| 第一次加入第三方已整理目录 | `扫描` | 导入影片、NFO 字段、本地图片和 NFO 演员关系。 |
| 第三方工具新增影片或修改 NFO、本地图片 | `扫描` | 发现新增内容，并同步未被手工编辑的 NFO 信息。 |
| 只浏览、搜索、查看演员或重启软件 | 不需要操作 | 直接读取已保存的 Jvedio 数据，不会重新解析 NFO。 |
| NFO 缺少资料，且影片身份明确 | `抓取元数据` | 可选地用 MetaTube 补齐仍为空的资料。 |
| 要补演员头像、别名等演员档案 | `重新拉取演员信息` | 只补 Jvedio 的演员资料和缓存。 |

`抓取元数据` 不是导入第三方目录的必经步骤。NFO 已包含所需资料时，第一次 `扫描` 即可完成接入。

## 数据如何处理

扫描会把 NFO 的标题、简介、日期、导演、片商、系列、标签、演员关系以及本地图片映射为 Jvedio 正常影片数据。之后列表、搜索、详情和演员页都读取 Jvedio SQLite，不会在日常浏览时反复读取 NFO。

你在 Jvedio 手工保存的影片资料或演员关系优先于后续 NFO 同步；未手工编辑的字段可在 NFO 内容变化后由下一次 `扫描` 更新。没有明确、无冲突标准番号的影片不会被猜测为远端身份，也不会自动请求 MetaTube。

`backdrops`、`behind the scenes`、`extrafanart`、`extrafanart_copy` 和 `trailers` 会作为资源目录跳过，不会被扫描成独立影片。

## 外部目录保护

下列操作都不会修改第三方目录中的文件：

- `保存媒体库`、`扫描`、`抓取元数据`
- `保存演员`、`重新拉取演员信息`、`编辑演员信息`
- `导出用户数据`、`导入用户数据`

因此，Jvedio 不会移动或重命名影片，不会生成、重写或删除 NFO，不会替换本地图片，也不会下载 NFO 中的远程图片 URL。它同样不会自动合并无标准身份的多文件影片。

## 用户数据迁移

`导出用户数据` 会保存 Jvedio 的目录源配置、已转换影片资料、演员关系、手工编辑和 Jvedio 缓存；不会复制外部影片、NFO、海报、剧照或资源目录。

在另一台电脑导入后，先让原影片目录可访问；路径变化时在库管理中改为新路径，再点击 `扫描`。当前导入会替换目标机器整份 Jvedio 用户数据，不支持按媒体库选择性合并。
